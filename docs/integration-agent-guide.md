# Integrate an existing Bean Counter CLI

Start at [START-HERE.md](../START-HERE.md). This route is for application integration with the local billing CLI. Repository implementation work follows the separate contributor contract in AGENTS.md.

Read [the capability record](integration-capabilities.json), [current requirements](../CURRENT-REQUIREMENTS.md), the [caller contract](billing-m2-cli-contract.md) and [operations/recovery](billing-operations.md). The current native baseline is v0.9.0 for macOS 26.6.2 arm64 and Ubuntu 24.04.5 x86-64/glibc 2.39. The pending source helper correction is not yet in those released archives.

Before a write, identify one business installation, explicit customer/source, immutable agreed terms, current authority and retained assent evidence. Generate application-owned stable delivery and semantic operation IDs and persist the exact request bytes privately. Application events assert work; they cannot choose authoritative prices or grant permissions. Synthetic examples are not real consent or authority.

The transport is an ordinary local process with CLI arguments, strict JSON files/stdin and JSON stdout plus exit status. Accept successful `content.generated` completed work in the approved fixed-price or one-unit integer-quantity profile. Request acceptance/job start is not billable work. Python report generation and Node drafting are the two proposed product mappings in [the readiness plan](oss1-readiness.md); broader business semantics need a separate review.

An authoritative base receipt is returned only after commit. Save it only after reconciling the complete target explanation and original operation. Supported history formats are statement `/2` at scale 2 and `/3` at scale 18; period statement `/4` is a separate immutable-close result. Never treat a preview, successful spawn, exit 0 without valid evidence, partial statement or CSV trailer as a charge/payment acknowledgement.

After an unknown response or exit 8, retain the original customer/source, request bytes and IDs and retry identically against the same installation. Preserve refusal/error output. Stop on integrity failure; do not delete locks or edit the database. Run one caller per durable private outbox and follow the [whole-installation recovery procedure](billing-recovery.md).

No remote API, payment provider, hosted setup, general linked-event pricing, arbitrary fee calculation, multi-host writer replacement, PostgreSQL billing or background recurrence execution is available in this profile. Capability metadata is descriptive and grants no execution or authority.
