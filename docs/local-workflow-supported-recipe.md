# Local declarative workflow candidate: supported recipe

This is the restricted Wave 2a source candidate, not a claim that the full workflow registry or Wave 2 is qualified. The existing released `ledger billing` product keeps its version-matched scope and behavior. Wave 2a.2 durability/financial checks and Wave 2a.3 exact-candidate QA/package gates must pass before this workflow candidate is handed to independent testers. No release is implied by the source checklist.

## Admission boundary

New local publication compilation, agreement acceptance, initial activation, and work admission check the same structural policy subset. Original committed source/plan loading, status, and identical retry do not rerate or run a new admission check. Existing authority, canonical-record association, original terms, current rights, head/absence, revision, financial topology and atomic-commit checks remain mandatory.

The allowed structure is one retail binding, one successful Work activity with caller-provenance facts, one fixed service rule, one attributable `app_final_cost` rule and declaration for that work, and one Outcome activity/family linked directly to the service component. The outcome schema has its declared code and occurrence assessor facts. Existing compiler constraints also retain the true predicate, own-work accepted-time window, exact amount/unit, and supported application allocation semantics. Names, prices, multipliers, maxima, and valid durations are input data; the gate does not recognize demo identifiers or a $3.25 input total.

New acceptance and initial activation additionally require the actual original Terms7 family causal-reversal clause, matching the selected family, service component and correction nomination. The app causal declaration must be present in the policy and match its exact accepted app terms. No clause, consent, authorization or default right is inserted. The already-existing work source-composition restriction is checked before these new agreements: the promised slots nominate one authenticated future work source and its original principal/enrollment. The accepting administrator is not substituted for that future worker. Independent source/principal compositions remain outside this candidate.

## Closed operation checklist

| Operation | Recipe requirement / boundary |
| --- | --- |
| Setup, source/customer evidence, party authorization and commitment consent | Actual local public prerequisites; retained identities and full terms, original/current authority and party mappings remain required. No remote authentication or payment execution. |
| Publication, acceptance, initial activation | Selected local Compiler7 or operator-resource Compiler8; Policy4, Terms7, local registry and canonical saved plan associations. Initial activation only. |
| `work.accept` | Successful work, fixed service plus pending attributable app cost; caller facts; empty required-proof/link/invocation arrays for this recipe. No failed-work or stage engine is claimed. |
| `evidence.retain` | App usage observation and final attributable cost; outcome code/occurrence fact attestations; family-close attestations. Exact subject, source, purpose and permanent assertion/call/provider identities remain checked. |
| `cost.finalize` / `cost.correct` | The one app component, its immutable original work/claim and accepted terms. Finalize and correction use their actual fixed original anchors; a correction retains its initial revision/T0 operand. |
| `outcome.submit` / `outcome.correct` | The one declared family, actual assessor proofs, original service basis, premium/discount/none, expected revisions and original non-sliding windows. Authenticated app-cost sibling heads do not replace the original root/outcome checks; full funding state stays selected. |
| `outcome.close` | Explicit no-success close with the declared attestation/source, or the independently authorized deadline-close path. Neither substitutes for the other. |
| `work.reverse` | Original authorized root reversal with required pending/finalized app and family causal inverses/permanent closure. Existing exact clauses and original/current rights are required. |
| Original status / identical retry | Saved request normalization, canonical committed operation/manifest/receipt/result associations and current read rights. A duplicate returns the original receipt and adds no operation or financial action. |
| Resource settings | Optional trusted private-installation finite/null settings; captured once per attempt and rechecked before commit. Null removes operational quotas, not financial/format/integrity checks. |

Successful quantity repricing is **not** part of this fixed-service recipe: quantity/source bounds alone do not create a Unit-price correction right. `quantity.correct` remains unavailable for this composition. Standalone link assertion, supplier invocation/AP, general Unit formulas, multiple families/bindings, multihop or predecessor-anchored families, stages, failed work, required work attestations/invocations, and agreement replacement/version-transition behavior are not advertised by this candidate. Broader registry/schema recognition is not executable capability. Those existing full-scope items remain tracked for Wave 2b.

## Error and recovery boundary

The private local construction mapper exposes only codes already declared by the exact local registry, including window, target, exposure and authority refusals. Unknown internal diagnostics retain the existing unavailable fallback, and the released shared mapper is unchanged. Configured resource refusals retain their sanitized setting/limit/observed diagnostics.

A refusal does not authorize changing accepted terms, moving timestamps, ignoring a current right, or resubmitting under a new identity. An unknown commit outcome is reconciled using the original identity. Read/status and original retries do not consume new retained-storage admission merely because the operator lowered a quota. Whole-installation restore and interrupted-write/reply-loss qualification are Wave 2a.2 evidence gates, not established by the happy-path bill alone.

## Evidence gates

The baseline source demonstrated one synthetic $1 service + $2 attributable cost + $0.25 premium, public separate-process status and identity retries with no duplicate append. That result is not evidence that every promised correction/reversal/closure has run. Wave 2a.1 closes the source/admission checklist; Wave 2a.2 must qualify the listed promised operations and relevant refusals on the coherent candidate before Wave 2a.3 publication preparation. Private proof databases, local paths and session logs are not publishable test fixtures.
