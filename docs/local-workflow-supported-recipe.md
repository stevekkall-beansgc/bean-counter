# Bounded local workflow checkpoint: supported recipe

These instructions target v0.11.0. Actual publication and native qualification are established by the matching GitHub Release and QUALIFICATION.json, which bind exact source, target, archive and binary hashes. Earlier source proofs and published archives retain their original identities. Billing contract v0.3 and billing schema 11 are unchanged; optional workflow activation uses schema 17.

The supported composition is one retail binding, one successful Work activity, one Fixed or integer Unit service rule, one independent True app_final_cost rule/declaration, and one Outcome family linked directly to the service component. A Unit quantity can be caller-provenance or genuinely attested through the existing worker/meter_quantity nomination. The additional predicate is exactly one Eq over a required caller-enum field in immutable accepted binding context; generic predicate grammar is not advertised. The app remains independent when the service condition is false. Names, prices, valid quantities/durations and maxima are accepted input data, not demo identifiers.

Original Work attestation uses its business subject before a WorkRef exists. Quantity correction requires a genuine replacement proof for the quantity field and preserves original Work quantity, rates, terms, evidence and receipts. EvidenceVerification authenticates the historical retention grant/principal/enrollment; current consuming rights are checked separately. VerifiedFact is derived immutable evidence, not a new one-use cost claim. All required original clauses, current rights, expected heads/revisions and dependent nominations remain mandatory.

For a matching service at quantity 3, rate $1, app cost $2 and 10% outcome, totals are **3 → 5 → 5.30 → 2 → 0**. Quantity 3→2 appends −3,+2,−2,−0.30; app/family close permanently. It does not reprice the premium to 0.20. Final reversal appends only −2.

For nonmatching service, Work still retains its exact root Decision/claim, proof, chain, capacity and independent app dependency, but no service Action/Target/family. Finalized totals are **0 → 2 → 0 → 0**, with only app +2 and −2; final root reversal emits no Action. Pending totals are **0 → 0 → 0**, retiring the real dependency without inventing a CostClaim; later finalize refuses TARGET_CLOSED. A selected exact-zero service is distinct: its selection/target/family topology remains. No zero Action is fabricated.

The current native capture uses the exact additive conditional Compiler8 contentRef. Old Compiler8/profile bytes are unchanged and old saved publications/receipts remain readable. Fresh old-profile publication is not claimed under a binary captured for the conditional profile. The package retains older fixtures/modules for source-profile development and original-history compatibility; start the native walkthrough in [workflow-conditional](../examples/workflow-conditional/README.md).

Public status and identical retry must validate the full original certificate and return exact original receipts without append. STATUS uses ledger-operation-status/1; SUBMIT uses ledger-operation-result/1. Same-key changed context refuses IDENTITY_CONFLICT. Original replay uses historical authority/custody/prestate and the exact saved member recipe, without today's NEW-admission filters. Unknown commit outcomes require the same installation/key/request; never replace identity, alter accepted clocks or silently replay a partially completed chain.

Operator resource quotas remain separate from commercial limits. Null settings do not waive format/integrity/financial checks, authority, cancellation or IO/coordination boundaries. Existing limits and atomic SQLite behavior remain unchanged. Retained original recovery, whole-installation restore, older-writer refusal and scoped fault evidence are recorded separately by source/target. Fault-worker stack settings are qualification conditions, not production limits or general/default-stack guarantees.

Standalone declared Work links, invocations, stages/failed work, general predicates, multiple bindings/families/sources, workflow economic statements, supplier AP/payment, hosting/distributed writers, online backup, signing/notarization and resource guarantees remain outside this checkpoint. Existing nonpayable cost-observation/component semantics stay later Wave2b obligations; optional provider/AP integration is not required for this checkpoint.
