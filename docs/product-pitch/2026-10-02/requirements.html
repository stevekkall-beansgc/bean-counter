THE EXPERIENCE WE WANT TO SELL

From agreement to an explainable receipt

  1. 01 / Bring the agreement

    Who pays, what counts, the price and who accepts the outcome.

  2. 02 / Connect one event

    Send a stable event ID and evidence for the supported outcome profile.

  3. 03 / Inspect the receipt

    See the calculation, policy version and accepted evidence.

  4. 04 / Send it downstream

    Export to your existing finance workflow. Payment collection stays with that system.

Adoption targets: an unfamiliar agent finds the safe entry point in 30 seconds; a person reaches a synthetic receipt within five minutes after installation. These are acceptance targets to test, not measured setup times.

WORK BACKWARD FROM THE PROMISE

Every promise needs a test before we sell it.

These are proposed requirements, not implementation authorization. P0 makes the existing engine easier to adopt. P1 qualifies a managed workspace. P2 adds operated delivery.

R01One understandable billing agreementP0 · Partial

Supports P01 · Free core

Versioned policy template: price, unit, currency, acceptance authority, effective time and correction rules. Plain-English preview alongside exact configuration.

Acceptance test

A prepared operator configures one fixed-price outcome without Rust or timestamp-format knowledge; invalid or incomplete terms are rejected before activation.

Current evidence / gap

Guided setup exists but the simplest path still requires about 31 answers in the reviewed source.

Evidence required before the promise goes live

Policy preview; invalid-input cases; observed setup recording

R02One trusted event contractP0 · Partial

Supports P01 · Free core

Document customer, outcome, event ID, event time, acceptance evidence and policy version. Publish schemas and examples for the qualified profile.

Acceptance test

A valid accepted outcome produces the expected obligation; an unsupported event is rejected with a stable error and repair guidance.

Current evidence / gap

Narrow outcome billing is demonstrated; broad chained-work behavior must be separately qualified.

Evidence required before the promise goes live

Schema fixtures; exact-version integration receipts

R03A defensible billing receiptP0 · Partial

Supports P02 · Free core

Expose the accepted evidence, calculation, policy version and correction history in machine-readable output and a readable explanation.

Acceptance test

A reviewer can trace an amount back to source evidence and agreement. Replayed input does not create a second obligation; corrections preserve history.

Current evidence / gap

Existing receipt and replay evidence is narrow. General exactly-once external delivery is not established.

Evidence required before the promise goes live

Replay, correction and explanation acceptance cases

R04Install without a toolchainP0 · In progress separately

Supports P03 · Free core

Native archives, checksums, supported-platform matrix and one consistent installation path. Reuse existing native-packages issue #5.

Acceptance test

A clean supported machine runs the version and synthetic walkthrough without compiling Rust; failure explains the supported alternative.

Current evidence / gap

Product owner’s local session owns native packages. Do not duplicate its work.

Evidence required before the promise goes live

Published artifact provenance; clean-machine qualification

R05Five-minute first receiptP0 · Proposed

Supports P03 · Free core

Synthetic sample, safe defaults, relative-time helpers, configuration file and a clear transition from demo to real customer data.

Acceptance test

Target: after installation, a new operator reaches and explains one synthetic receipt within five minutes without assistance. Report observed time and failures.

Current evidence / gap

An acceptance target, not a measured onboarding promise.

Evidence required before the promise goes live

Timed observation with unfamiliar users and no production data

R06Thirty-second agent orientationP0 · Proposed

Supports P04 · Free core

A single operator quickstart, task-oriented AGENTS.md routing, a thin CLAUDE.md compatibility pointer where needed, capability manifest and versioned input/output schemas.

Acceptance test

An unfamiliar agent identifies supported version, safe entry point, required inputs, irreversible steps and success criteria within 30 seconds. It declines unsupported capabilities.

Current evidence / gap

Contributor instructions exist; operator discovery is incomplete. Documentation alone does not enforce permissions.

Evidence required before the promise goes live

Cold-start evaluation; schema validation; refusal cases

R07Reliable integration handoffP0 · Gap identified

Supports P04 · Free core

Align Python/Node outbox helpers with qualified statement versions, saved acknowledgments, stable IDs, retry semantics and command-specific help.

Acceptance test

Statement/2 and supported statement/3 receipts survive send, acknowledgment loss, restart and retry without silently losing a receipt or duplicating an obligation.

Current evidence / gap

Reviewed helpers reject statement/3; candidate correction has synthetic evidence only.

Evidence required before the promise goes live

Exact-version engine plus helper integration and restart tests

R08A private managed workspaceP1 · Not available

Supports P05 · Managed workspace

Authenticated API, business isolation, least-privilege access, single-writer control, local storage ownership, exports and bounded capacity.

Acceptance test

One business cannot read or write another’s records; concurrent requests are safely serialized; capacity limits are explicit and observable.

Current evidence / gap

The reviewed engine is a local SQLite CLI. A hosted multi-customer service is new work.

Evidence required before the promise goes live

Isolation and authorization tests; failure handling; capacity evidence

R09Recovery that actually worksP1 · Not available

Supports P05 · Managed workspace

Consistent backups, retention policy, monitored backup age, restore procedure and controlled upgrades with rollback rehearsal.

Acceptance test

Restore a representative workspace and reconcile its records and receipts. Publish only recovery-time and recovery-point commitments supported by drills.

Current evidence / gap

No verified hosted recovery or uptime guarantee. SQLite is viable with disciplined local-volume and writer ownership.

Evidence required before the promise goes live

Restore drill; reconciliation report; upgrade/rollback drill

R10Operated event deliveryP2 · Not available

Supports P06 · Managed delivery

Approved source/destination adapters, durable queue, deduplication keys, bounded retries, failure quarantine, alerts and operator replay.

Acceptance test

Dropped acknowledgments, duplicate events, out-of-order arrival and downstream outage produce visible, recoverable outcomes with no silent data loss in the qualified profile.

Current evidence / gap

We transport customer-provided facts; we do not decide whether their business outcome is true.

Evidence required before the promise goes live

Fault-injection traces; queue state; operator recovery evidence

R11Predictable infrastructure pricingP1 · Proposed

Supports P07 · Commercial

Monthly workspace capacity bands; later connection/workload bands; included reliability and explicit limits. Measure operating and support costs before prices.

Acceptance test

A buyer can identify included storage, retention, traffic, support and overage behavior before agreeing. Unit economics remain viable under measured use.

Current evidence / gap

No price has been approved. No revenue share, seat fee or correction fee in this proposed offer.

Evidence required before the promise goes live

Cost model; buyer interviews; approved offer and terms

R12Keep control and leave cleanlyP1 · Partial

Supports P08 · Free core + managed

Portable exports covering policies, events, obligations and receipts; documented version compatibility, migration rehearsal and offboarding process.

Acceptance test

A customer can export a sample managed workspace and verify equivalent records in a supported self-hosted environment.

Current evidence / gap

Local records exist; hosted export/import parity and migration are unqualified. Postgres is a later need-led option.

Evidence required before the promise goes live

Round-trip reconciliation; documented ownership and retention terms
