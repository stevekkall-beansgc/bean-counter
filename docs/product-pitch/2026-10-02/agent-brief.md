# Bean Counter: agent entry point

Status: PRODUCT PROPOSAL, not a running service contract. Date: 2026-10-02.

## Read in this order
1. product.json: offers, availability, prerequisites, exclusions and targets.
2. requirements.json: stable requirement IDs and acceptance evidence.
3. The pinned repository README and operator docs linked on the page.

## Operate safely
There is no Bean Counter service API or checkout on this pitch site. No commands here authorize engine execution, installation, spending or deployment. Determine the real installed version and qualified profile before using repository instructions. This repository snapshot is public; it does not expose a hosted engine API.

## Product truth
The reviewed engine uses local SQLite. Native-package work is separately owned in bean-counter issue #5. Managed hosting, remote authentication, operated pipelines and Postgres are proposed, not available offerings. Broad chained-work support is unqualified. Thirty-second orientation and five-minute first receipt are test targets, not measurements.

## Commercial boundary
Keep the self-hosted product useful. Charge for optional operated infrastructure: workspace runtime, storage, recovery and later delivery connections. Policy and monetization guidance remain part of adoption. Prices and service commitments are undecided.

## Human acceptance
The product owner reviews the offer and requirements. Passing a test or changing a board field does not authorize a new build or mark the work accepted.

## Product flow
Customer terms, work/usage events and authorized acceptance/corrections feed the local engine. The selected supported profile resolves terms, preserves history and retry identity, calculates amounts and reconciles billing periods. Outputs include charges/adjustments/totals, policy references/receipts/history, and supported JSON statements/finance CSV. M5 source-built qualification must not be attributed to older native packages. See product.json flow for structured fields.

## Technical boundaries verified 2026-10-02
Read product.json technical_capabilities. Supported local M4/M5 lifecycle links work/usage, charge, optional authorized outcome adjustment, append-only correction and immutable period close. Arbitrary generation-publication-acquisition chains, multiple billable milestones per agreement and end-to-end supplier obligations remain deferred. Customer billing schedules and organization fiscal calendars are separate; reports pin version and snapshot. Uncertain commit results require original-identity reconciliation; never assume rollback.

## Developer positioning
Do not rebuild billing for every product. Products within one business connect via the supported local CLI/JSON interface. The client still owns event instrumentation, customer mapping, stable retry IDs, error handling, schema compatibility and downstream export mapping. This is not a hosted HTTP endpoint, universal drop-in SDK or payment connector.
