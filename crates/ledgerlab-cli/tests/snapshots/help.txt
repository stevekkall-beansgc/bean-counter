Ledger Lab — chain events, compose pricing, explain the result locally.

Usage: ledger [--config PATH] [--format text|json] COMMAND

  init [DIR] --demo          Create a new/empty local sandbox (default: .)
  accept FILE|-             Accept one event from a JSON file or stdin
  preview FILE|-            Estimate without journal writes or commit
  explain EVENT_ID          Read a stored event (external or canonical ID)
  explain --chain CHAIN_ID  Read accepted decisions in chain order

Global options may appear before or after the command:
  --config PATH             Config file (default: ./ledger.json)
  --format text|json        Human output or one stable ledger-cli/1 JSON object
  --json                    Alias for --format json
  --no-color                Accepted; output is always plain text
  --help, -h                Show help, including after a command
  --version                 Show internal development version

Start: ledger init ledger-demo --demo
Then: cd ledger-demo
      ledger preview examples/generated.json
      ledger accept examples/generated.json
      ledger explain --chain demo-slice

Local commands support only the synthetic Phase 1 generation demo:
demo-customer owes demo-host USD 0.80 for generation (USD 1.00 charge
less USD 0.20 customer discount). Dispatch is held; no payment is executed.
Upcoming story (documentation only): generation -> publication -> acquisition,
a separate customer discount, paid tools and BYOK/platform-funded responsibility.
Linked events, outcomes and reversals cannot yet be saved or previewed.

No Docker, Node, cloud account, provider key, or server is required.
Config uses strict JSON in ledger.json. Legacy JSON-in-YAML files require
--config ledger.yaml explicitly. Building requires Rust and a native C toolchain;
offline builds require dependencies already cached. See docs/quickstart.md.
Preview is an estimate, never a receipt; opening/locking may touch SQLite
sidecars. File inputs are regular files, at most 256 KiB.

Exit codes: 0 success; 2 usage/config/input-file; 3 rejected/not found;
4 conflict; 5 waiting; 6 unauthorized; 7 busy/unavailable; 8 outcome unknown;
9 integrity failure. Retry unknown outcomes with the same event identity.

Ordinary local billing (separate installation):
  billing setup DIR [--setup FILE]     Guided, confirmed private setup
  billing init DIR --setup FILE        Noninteractive JSON setup
  billing [--directory DIR] accept FILE|-
  billing [--directory DIR] outcome FILE|-
  billing [--directory DIR] correct FILE|-
  billing [--directory DIR] permissions [FILE|-]
  billing [--directory DIR] explain TARGET_ID
  billing [--directory DIR] statement --customer CUSTOMER
  billing [--directory DIR] export-csv --customer CUSTOMER --snapshot HASH --mapping FILE --output FILE
Billing output is JSON (pretty-printed unless --json). No payment or tax invoice.
