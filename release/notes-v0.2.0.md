# Bean Counter 0.2.0 — local finance CSV export

The local SQLite billing command now exports a complete, pinned finance CSV from retained, verified posting records. The export preserves original record and obligation identities, exact signed USD atoms, correction and reversal references, and explicit operator-supplied party/account labels. Repeated exports of the same snapshot and mapping are byte-identical. Existing output paths refuse replacement; file-write failures do not change billing history or acknowledge delivery.

Follow the [owner end-to-end walkthrough](https://github.com/stevekkall-beansgc/bean-counter/blob/v0.2.0/docs/finance-e2e.md) using the included synthetic inputs. It covers customer/terms setup, $2.50 work items, duplicate retries, a rebate, replacement correction and reversal, explanation, JSON statement, repeated CSV reconciliation and an optional quiescent verification copy. The expected five-decision result is six posting rows totaling **500 USD atoms ($5.00)**. The file is a generic finance export; it is not a vendor import, tax invoice, payment, or delivery acknowledgment.

This is a backward-compatible addition to v0.1.0. Cargo packages are version 0.2.0; the local billing facade contract is `v0.2`. Frozen economic records and store schema are unchanged. Source and the native archive will identify the exact release commit. Native testing covers macOS 26.6.2 on Apple silicon. The author-built archive is unsigned; no clean-account Gatekeeper launch, other runtime platform, minimum Rust version, reproducible build or signed provenance claim is made.

Resource guarantees, PostgreSQL product support, multi-host writer replacement, advanced comparison, remote authentication and hosted operation remain deferred. Users provide and manage storage and backups. Independent acceptance remains platform-blocked; author testing, hosted CI and the owner's later end-to-end test are separate evidence. No owner test result is claimed by this release.
