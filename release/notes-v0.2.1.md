# Bean Counter 0.2.1 — clearer outcome examples

The local billing quickstart now spells out the absolute outcome-window order and explains how to handle `OUTCOME_WINDOW`, `STALE_REVISION` and uncertain commit results. The included synthetic demonstration adds four fresh-store examples: completed work with no outcome (`+2` atoms), success (`+2,+98`), an explicit unsuccessful-by-cutoff outcome (`+2,-2`), and a correction from success to unsuccessful (`+2,+98,-98,-2`). It checks complete statements and exact totals, and verifies that retrying the same success outcome retains its receipt.

The finance CSV workflow remains available. Follow the [v0.2.1 owner walkthrough](https://github.com/stevekkall-beansgc/bean-counter/blob/v0.2.1/docs/finance-e2e.md) with `--checks` to run the new cases, plus the original six-posting `$5.00` reconciliation. The examples use illustrative operator evidence and windows extending into early 2027; they do not verify a real model result, create a capacity reservation or automatically credit an absent outcome.

This is a patch release of the existing local SQLite profile. No billing-core rule, store schema, frozen economic record or external service was added. Cargo packages are version 0.2.1; the local billing facade contract remains `v0.2`. Native testing covers macOS 26.6.2 on Apple silicon. Independent acceptance remains platform-blocked; owner acceptance of v0.2.0 and author checks of these examples do not constitute formal independent review. PostgreSQL product support, resource guarantees, multi-host operation, remote authentication and hosting remain deferred.
