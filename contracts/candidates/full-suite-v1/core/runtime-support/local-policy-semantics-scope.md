# Local policy semantics implementation scope

This additive binary-owned profile reuses the existing Policy4, Product1, FactSchema1, CompilerDescriptor8, CompiledPlan8 and declared-link operation registry. It defines no new economic operation, authority, limit or public payload. All older profile assets and original recipes remain immutable.

The supported scalar predicate grammar is true/false/eq/lt/le/gt/ge/in/all/any/not over declared activity facts and authenticated immutable accepted-binding facts. Equality and membership are typed; ordering is numeric or timestamp only. Missing follows the existing three-valued algebra; only True selects. Type/domain/provenance validation, canonical literal normalization and finite producer-implication proof remain required, including optional fields. Descriptor type/operator lists are not a Cartesian support promise.

Exact Product-declared positive reduced unit ratios normalize quantity under declared precision and rounding; all pricing, original reload, correction, funding and capacity consumers must share that conversion before the profile is exposed. A changed root predicate can alter corrected root money without creating a new original Target/family, while existing causal closure obligations remain.

Direct and declared-hop family topology use their exact existing payload/claim versions and original selector/member rules. No fresh right follows from a relation or normalized value. Saved original recovery uses original capture/descriptor/terms and historical certificate, without today's NEW admission.

Operational source/funding_mode contexts remain excluded pending their separate operand disposition; status, invocation-dependent Ref/provenance, supplier books, caps, shares, stages, late links and cross-binding execution are not advertised. This is implementation support metadata, not a runtime qualification, resource guarantee or full-Wave2b completion claim.

For this profile, the initial one-configured-source subset in Agreement Ready §3 is extended to the already specified local-owner multi-source case (Current Requirements, local authority/isolation; S12 §3.3). The unchanged authenticated Setup operator administers an explicitly enrolled second canonical source through the existing source enrollment/change payloads. The target source must equal its permanent canonical namespace and its principal must equal that actual local operator. The administrative operation identity and root remain the owner's identity; a target source does not acquire administrative rights. Distinct principals, aliases and remote delivery authentication remain unsupported.

A new-profile evidence-retention request under that second source is admitted only after resolving its committed enrollment and current state/grant, exact original accepted source nomination and declared FieldDef provenance slot, matching the actual local operator, source, scope, customer, Product, activity, operation, rights and trusted time. A requested source name or local ownership alone does not supply this proof. Original proof consumption verifies its original issuer authority and enrollment without requiring the issuer to remain current; consuming Work/correction authority remains independently current. Old profile admission and original-record bytes are unchanged.
