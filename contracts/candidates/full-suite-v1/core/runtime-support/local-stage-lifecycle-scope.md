This additive exact profile reuses Policy4, Plan8, Work1 and the existing evaluator, execution coordinator and limits. Earlier local profiles remain immutable. The shared namespace meaning is the approved explicit same-principal enrollment-to-canonical-owner association, with independent grants and first-event source pricing on aliases.

The defining stage dictionary and identities are the reviewed fixed StageDeclarationInput/StageInstance/StageState/StageClosureClaim forms. Permanent identity is store, scope, agreement, chain and stage; customer and Binding are authenticated association. The first accepted expected Work fixes the clock. Without earlier activation, trusted stage-close acceptance is T and must not exceed original D. No precursor backdating, reopening or fabricated component Outcome claim is permitted. Invocation inputs reuse exact InvocationAuthorize1; the structural aggregate maximum512 never raises per-member16 or any existing action, decision, byte or capacity bound.

Component mode supports named earlier-producer bases, additive/sequential discounts, multiple independent families and declared selector paths within the existing four-edge dictionary bound. Observed cost remains nonpayable. Closure-share mode is a separate composition island: one unconditional retail cap on the current closure premium, never below booked prior net, and at most one supplier share of the current net after cap under original invocation capacity and supplier rights. It does not compose with component OutcomeFamily or pass-through/final-cost pricing. No general running cap, floor, recursive share or replenishment is introduced.

Current source and historical original source remain separate. Every mutation and terminal path checks actual selected current roles plus original terms; recovery uses saved cutoff, manifest, producer, custody and receipt evidence. Storage support does not establish semantic support. Capability metadata is not execution qualification: complete consumers, source/input map and financial/recovery proof are required before supported admission.

The accepted StageDef explicitly requires authorization_source_slot. Resolve that slot through the original accepted Binding and authenticate the actual caller against original and current invocation.authorize plus invocation/read permissions. The slot is separate from expected workers, closure assessor and supplier authority; an empty invocation_inputs list creates no supplier authority. There is no inferred or default authorization slot. This additive StageDef definition applies only to this Stage profile; earlier closed dictionaries remain unchanged.

Supplier account enrollment uses the existing ledger-cost-authority-enroll/1 authority.change input and CostEnrollmentAuthority1/OwnerActivation/CostAuthority1 definitions through the same held local administrative owner and append coordinator. Its exact Stage registry tuple applies before Binding selection.
