## Closed records and hashes

`build-provenance.schema.json` is the exact closed shape contract. BuildSourceInventory body contains schema, entries and recipe version. Each entry is `{path,bytes,sha256}`; bytes is a canonical unsigned decimal string, sha256 raw lowercase64hex. Paths are UTF8 repository-relative `/` paths, no empty/dot/dotdot components, backslashes, absolute paths or normalization aliases. Sort entries by UTF16 path order; duplicate paths reject. Hash exact raw file bytes, without newline/encoding conversion. Inventory digest is `sha256:`+SHA256(`bean-counter/build-source-inventory/1`||NUL||JCS(inventory)). No executable, generated build metadata, target directory, VCS internals, local database or private credential/configuration is a source input.

Inventory selection `bean-counter-build-inputs/1`: tracked and present untracked regular files under crates/** except target directories, root Cargo.toml/Cargo.lock/rust-toolchain.toml (or rust-toolchain when present), plus every contract file actually included by the builtin compiler/support factory. Include Cargo/config and build-script inputs that affect compilation, including .cargo/config.toml when used. Include all workspace crate manifests/build.rs/source/testkit files because they may affect build resolution. Ignore nonbuild docs unless embedded; hash embedded docs as inputs. Reject symlink/submodule/escaping source inputs in this initial capture recipe rather than follow outside roots. An undeclared build input or external code-generating input makes this recipe unsupported, not “clean”. Build tooling must supply the complete explicit embedded-contract list and dependency/toolchain metadata; runtime requests cannot select it.

BuildSourceSnapshot is `{base_commit,state,inventory_digest,file_count,total_bytes}`. base_commit is the actual build-time git HEAD40hex, never runtime git lookup. `state=clean_commit` only if the selected inventory matches the selected files of that commit exactly, index/worktree changes affecting those inputs are absent, and no additional relevant untracked files/configuration affect the build. Otherwise use `worktree_snapshot`; HEAD is only its base, not a claim the binary was built from that exact clean commit. Unrelated nonbuild edits do not invalidate a scoped clean build-input claim. Inventory capture must be stable: compare before/after build or build from an immutable captured input tree; changes during compilation invalidate the artifact's provenance. An unavailable git base or unverifiable inventory is unsupported for this initial actual-publish path; no zeros, guessed SHA or synthetic fallback.

BuildInputs is `{schema,source,recipe}`. BuildRecipe includes actual package_name/version, build_profile, target, features (sorted unique ASCII strings), rustc_version, cargo_version, rustflags (ordered array), cargo_lock_digest, compiler_ref. These values are captured by trusted build tooling and embedded in the executable, never populated from operation JSON or runtime environment fallback. Tool versions are actual compiler/tool outputs, not guessed crate metadata. `cargo_lock_digest` is tagged raw SHA256 of exact Cargo.lock bytes. Rustflags must contain the effective explicit flags; secrets/absolute private paths cannot be silently redacted to alter build identity—unsupported capture fails until built with an appropriate recorded recipe. Dependencies outside repository are identified by locked Cargo dependency data/tool versions; this recipe does not attest their reproducible provenance or hash every transitive compiler input.

BuildManifest body is `{schema:"ledger-workflow-build-manifest/1",build_inputs,executable:{sha256,bytes,observation:"stable-current-executable-file/1"}}`. It contains no clock, host path, hostname or mutable source-directory lookup. Canonical body ≤65536bytes; BuildInputs same bound. Inventory ≤1048576bytes/8192entries, each input size≤2^63−1 and total checked≤2^63−1. These are build-metadata capture bounds, not new economic/profile limits. Exceeding them refuses provenance capture; no truncated inventory. Inventory is a build evidence artifact with digest/count/total embedded in BuildInputs; runtime journal need not store the entire source tree/inventory. The local builder must retain the inventory alongside its build evidence if later source capture audit is desired. Absence of that external evidence limits independent source verification, not original receipt availability.

`build_manifest_digest = sha256:`+SHA256(JCS(BuildManifest)). No fields omitted, no LF, no domain prefix for this existing digest field. Retained record kind `workflow-build-manifest`, schema above, Ref ID `wdoc_`+hex(H_workflow-document([schema,body])), digest H_workflow-document([schema,body]) using existing frame. Content-addressed record identity is distinct from the raw build_manifest_digest. Closed Publication.provenance stays exactly its existing three fields: source_sha=BuildInputs.source.base_commit; binary_sha256=BuildManifest.executable.sha256; build_manifest_digest=raw canonical manifest digest. This mapping preserves shape while making source state explicit in retained manifest.

## Trust derivation and persistence

Trusted local coordinator obtains a private `VerifiedBuildProvenance` from compile-embedded BuildInputs plus the running executable file opened through the OS current-executable facility. Stream raw SHA256 and byte count from the same open handle; validate regular-file identity/size/metadata stability before/after read and fail closed on substitution/change. Where the OS permits comparing launched-image identity, verify it. `stable-current-executable-file/1` states exactly an observation of that executable file; it does not prove mapped memory, dynamically loaded libraries, independent build authenticity or reproducibility. Do not call a declared base commit an independently verified build attestation. The local administrator/build chain remains the trust root, as with existing local authority.

The pure core may validate a typed supplied BuildManifest but does not perform OS hashing or independently authenticate it. Store accepts only coordinator-produced verified provenance on the private append path; no caller-owned manifest/provenance or public raw append. A persisted manifest cannot authorize a fresh request merely because its hash validates. Fresh publication requires the manifest's compiler_ref equal the actual builtin support anchor used for compilation. Source capture/recipe and executable observations are separate so executable SHA never needs to embed itself (no self-hash cycle).

Retain BuildManifest atomically in workflow_documents and the publication verification manifest. It is not a compiler source document, source locator, FactSlot, descriptor-normalization input, financial fact or authority grant. Initial actual local publication has exactly one corresponding build manifest; dependency lookup uses publication.provenance.build_manifest_digest and requires exactly one retained matching canonical body plus projection equality. Verification member ceiling increases explicitly from147 to148 (128sources+16authority+plan+publication+operation+one build manifest). Actual fresh local fixture with six sources/oneauthority becomes11 verification members and13 retained envelopes. Historical twelve-envelope synthetic fixture remains historical PUB-ENC-01; it is not a valid actual-runtime provenance fixture.

Semantic alias reuses the original publication **and its original build manifest**, even if current executable/support build changes while producing identical supported source/plan. Current attempt's actual provenance may be operational evidence, but must not replace original. Original-key retry/status reads original retained manifest/provenance after current read authorization, with no current executable, source tree, old binary availability or current compiler equality requirement. Reopen verifies canonical digest, Ref/member closure and three-field projection; it cannot rerun the historical source build or prove its authenticity. Missing/tampered retained manifest for a PUB-BUILD-01 operation is integrity failure, not permission to synthesize from the current process.

Profile B charges newly retained build-manifest canonical bytes once per unique workflow_documents row, plus existing operation wrapper meter. Alias reusing the old manifest adds zero manifest-document bytes. Existing PUB-ENC-01 synthetic meter examples remain specific historical examples; actual PUB-BUILD-01 totals require new independent vectors. No changing historical expected amounts/bytes to make implementation pass.
