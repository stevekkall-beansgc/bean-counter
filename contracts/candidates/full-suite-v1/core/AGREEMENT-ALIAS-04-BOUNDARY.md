# AGR-ALIAS-04 — honest authority for new-key agreement aliases

Astra, 2026-10-13. Additive candidate under AGREEMENT-BOUNDARY §§3–5 and AGREEMENT-READY-AMENDMENT §6. These already require same-intent new-key agreement aliases to preserve original results/heads without new admission, while still requiring current administrative read/submit. AGR03 authority/2's admit/stop union cannot honestly encode this after source revocation/expiry. This packet repairs that representation; it does not create new admission authority. Historical AGR03 schemas, registries, fixtures and freeze hashes are unchanged. Independent encoding/semantic review and implementation qualification required.

## 1. Branch order and actual actor

Authenticate current store/scope read first. Resolve original OperationKey and saved descriptors/evidence before any new branch; same-key exact retry returns its original receipt without new records, current source grant/time/CAS or new schema selection. Same-key different normalized original request is IDENTITY_CONFLICT. Current read denial still denies disclosure.

For a genuinely new key, normalize against exact immutable original documents under the applicable registered descriptor recipe. Look up the permanent semantic acceptance key or activation transition key. Compare original **intent**, not a reconstructed Binding with today's timestamp: accept compares complete normalized payload excluding only documents transport; activate/revoke compare exact original payload including expected_revision, evidence and explicit effective input. An already matched at_commit intent keeps its originally resolved time. Exact source/document/body identity remains required; no source alias remap or changed terms are treated as equivalent.

Only a verified equal semantic intent enters `semantic_alias`. It requires actual current private LocalOwnerAdmin, current administrative store/scope read and submit authorization and actual supported Setup.source mapping. Those are existing local administration checks, **not** SourceGrant permissions named agreement.accept/agreement.activate and not legacy source read/submit grants. Holding Owner alone, supplying a root Ref, or uploading an authority body cannot create the private capability. Source remapping remains unsupported; no invented Setup generation or rebind history.

The alias records an existing result. It does not re-check current work-source validity, binding interval, assent availability for a new admission, original effective time or agreement-head CAS. It does verify the retained original authorization/assent/terms/result origin under its original profile, and it reads the latest verified state of the **original binding's selected enrollment** under the existing ordered locks. Do not use the greatest revision from unrelated A/B grants. Changed/missing/corrupt lineage is integrity/resolution failure, not a made-up active grant. Current expired/revoked state is honestly recorded below. New nonmatching intent still takes the ordinary fresh/semantic-conflict path with unchanged admit/stop rules.

## 2. Exact new closed authority and operation dictionaries

`agreement-alias-04.schema.json` supplies only additive root variants; copied old definitions do not acquire a new freeze. `AgreementAliasAuthority` schema=`ledger-workflow-agreement-authority/3`, purpose=`semantic_alias`, has exactly:

`operation, actor, source, scope, customer, agreement_id, local_admin_ref, original_operation_ref, original_intent_ref, accepted_agreement_ref, binding_ref, binding_source_namespace, source_observation, observed_at` plus schema/purpose.

Operation is agreement.accept|agreement.activate|agreement.revoke. All names/Refs/times use existing bounded normalized types. No optional defaults. original_operation_ref must be the earliest **non-alias** committed operation that introduced the semantic result; alias chains are flattened by verified lookup, never by trusting a caller Ref. original_intent_ref is its exact retained AgreementOperationIntent. accepted_agreement_ref/binding_ref resolve the original accepted binding; accept obtains it from its original accepted result, activate/revoke through their retained binding. Operation kind, store/scope/customer/agreement/namespace and exact original result set must agree. local_admin_ref is a retained real local root snapshot whose root/mode/source identity matches the current private capability; that immutable body is not itself current authorization.

`source_observation` reuses AGR03's closed StopSourceObservation dictionary, without treating alias as stop:

- Revoked: enrollment_ref,state_ref,revision,status=`revoked`, **no grant field**.
- Active: enrollment_ref,state_ref,revision,status=`active`,grant_ref,grant_time_status=`valid|not_started|expired`.

The state Ref/revision and optional grant match the actual selected current SourceState. At trusted observed_at, classify starts_at≤t<ends_at as valid, below start as not_started, at/after end as expired. All are diagnostic/current-state facts; none supplies fresh billing permission. Original broader grants remain historical dependencies and are never mislabeled current. This branch has no source_grant_refs/assent_refs admission fields.

`AgreementAliasOperation` schema=`ledger-workflow-agreement-alias-operation/1` has existing operation fields `{schema,key,kind,contract,request_evidence,authority_snapshot,accepted_at,commit_sequence,result_refs}`. authority_snapshot is strictly AgreementAliasAuthority, its operation equals kind; result_refs equals the original non-alias operation's result_refs exactly. New intent, Binding, AcceptedAgreement, HeadTransition or ActivationTransition is forbidden. New actual time/sequence belong only to the alias operation/authority/receipt; original records keep original time/revision. Administrative-purpose2 and PublicationAuthority cannot occupy this body. Conversely authority3 cannot authorize any fresh admit/stop body.

Alias authority is retained once as workflow-authority using existing document hash framing. Alias operation is workflow-operation using existing complete OperationKey semantic ID and record digest; the new schema differentiates its body. No new operation verb or customer request field is introduced.

## 6. Error and implementation handoff

Use the existing registered errors: missing current local-admin/read/submit or wrong actual supported source mapping → AUTHORITY_REQUIRED; same OperationKey with unequal saved normalized intent → IDENTITY_CONFLICT; same permanent agreement/transition identity with changed intent → SEMANTIC_CONFLICT; missing immutable dependency → DESCRIPTOR_DEPENDENCY_MISSING; body digest mismatch → DOCUMENT_DIGEST_MISMATCH; malformed closed variant → INVALID_SHAPE; inconsistent retained origin/result/head/source association → INTEGRITY_FAILURE; unavailable pinned registry/verifier → UNSUPPORTED_SCHEMA_PROFILE; exact Profile B overflow → CAPACITY_EXCEEDED; manifest member/resolved-byte overflow → PROGRAM_BUDGET_EXCEEDED. No error implies a successful fresh admission. A failed current read does not reveal whether the original key exists. Fresh unrelated admission after source loss remains AUTHORITY_REQUIRED; an existing equal intent is necessary to select alias at all.

Pure core may construct a typed alias only from verified original non-alias result/intent and host-supplied private current administrative/source observation capabilities. Store mechanical commit consumes the prepared immutable plan with **ProjectionNone**, verifies locked source state and original semantic mapping remain selected, and charges exact Profile B delta. It must dispatch authority3/op-alias1/manifest-alias1 together under this new registry. Reusing old authority2 classifier or accepting a caller-supplied authority3 is unsupported. Original-key recovery remains earlier and uses the saved recipe. Selected vectors cover ordinary accept/activate/revoke; activation-replace aliases and other source states require their own independent histories before a broader runtime claim.
