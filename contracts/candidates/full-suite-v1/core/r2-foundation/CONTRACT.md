## 2. Exact pure interfaces

These are internal Rust/API data contracts, not new public operation wire formats. Rust field spelling may follow repository conventions; the information and trust distinctions are mandatory.

`compile_selected_program(input: SelectedSourceInput, support: &SelectedCompilerSupport, meter: &mut CoreMeter) -> Result<SelectedProgram>`:

- `SelectedSourceInput { documents: Vec<canonical JSON bytes>, root_policy_ref: DefinitionRef }`. Reject duplicate identities/duplicate semantic source keys rather than coalescing them; validate exact source closure and typed normalized bodies. Preserve1MiB source closure, per-definition bounds,4MiB plan bound and existing compiler-work ceiling.
- `SelectedCompilerSupport` has a private builtin constructor; test-only explicit synthetic construction is not exported to production. Exact descriptor body and Ref must match separately supported code.
- `SelectedProgram` has private fields: exact normalized source documents, original descriptor/plan bytes and Refs, typed ordered instructions/paths, parsed scalar operands, and `StaticAnalysis`. Its public read accessors expose bytes/Refs, not mutation.
- `StaticAnalysis` contains actual declared field/rule/path counts, interval calculations, component/binding coverage and compile-meter usage. It has **no** `CheckedCapacityProof` or future-runtime maximum assertion. Encoded CompiledPlan.worst_case remains the reviewed profile ceiling constants; separately prove the applicable selected source bounds rather than pretending constants are measurements.

`draft_transition(program: &SelectedProgram, context: &DraftContextData, payload: &[u8], records: &[RecordInput], state: &DraftStateData, meter: &mut CoreMeter) -> Result<DraftTransition>`:

- `RecordInput { reference: ExactRef, canonical_body: bytes }`. References retain kind/id/digest; exact known kind/schema/domain and semantic ID are validated when consumed. Reject duplicate supplied Ref identities, conflicting IDs/bodies, unknown required kinds, noncanonical bodies and missing reachable operands. No external resolver, database or clock.
- `DraftContextData { key: OperationKey, actor: string, canonical_economic_namespace: string, installation_mode, received_at, accepted_at, authorities: Vec<AuthorityContextData>, source_observation_inputs: Vec<RecordInput> }`. Times are explicit validated data. `source_observation_inputs` are explicitly pending coordinator-derived observation/verifier DATA for this draft, separate from retained records and historical seeds. The constructor validates their hashes and source/root/time relationships, echoes required newly introduced bodies into its draft, and does not authenticate their audit claims. They cannot serve as historical financial originals or bypass current source checks. The key fixes store/scope/source. Mode follows the existing authority dictionary; synthetic fixture mode is not a deployed trust mode. No arbitrary JSON `verified` field exists.
- `AuthorityContextData { source_slot, enrollment_ref, current_state_ref, current_grant_ref, original_grant_refs, binding_ref, accepted_agreement_ref, activation_ref, authority_observation_ref }`. One unique row per actually required original nominated slot. Exact evidence refs come from the normalized payload/family-closure entries, not a free authorization override. Actor/source/customer/scope are checked against the resolved enrollment, state, grants and original binding. A duplicate or unused authority row refuses.
- `DraftStateData { chain_head: Option<Ref>, decision_heads: Vec<{decision_id, revision, reference}>, family_heads: Vec<{target_ref,family_slot,revision,reference}>, work_claims: Vec<Ref>, outcome_claims: Vec<Ref>, links: Vec<Ref>, evidence_verifications: Vec<Ref> }`. Each is an exact snapshot input, not an authenticated host claim. Canonical key ordering and unique keys are required. Every referenced body must resolve. New-work absence is represented by absence, never fabricated revision0. Validate original and current revisions, the complete selected dependent closure, permanent claim/token uniqueness within supplied indices, exact link selection and existing pre-close generation. The future host must prove index completeness under locks; this pure API cannot.
- Supported payloads retain their reviewed schemas: work.accept, fact-attestation retain, outcome.submit, outcome.correct, quantity.correct (including causal2), work.reverse (including causal2). Dispatch by operation/schema and the accepted per-recipe tuple, never business name. Constructor membership is narrowed explicitly if an operation remains unimplemented; no successful empty placeholder.

`DraftTransition` contains: normalized payload; exact new `{Ref,canonical_body}` envelopes in acyclic construction order; ordered evaluation-step sequence; proposed decision/family/chain heads; selected claim/link introductions; prospective dependency **descriptions** keyed by original root/target/family; exact consumed Ref set and history edges; `MeterUsage`; and a fixed list of unresolved admission obligations. It excludes DependencyRecord/CorrectionCapacity, financial operation/manifest/receipt and a commit token. There is no production conversion from this type to a committable financial result in this foundation.

`replay_draft(program, saved_context, saved_payload, saved_records, saved_state, expected_draft, meter)` invokes **the same `draft_transition`**, then compares all resulting bodies/Refs and proposed heads. It does not use current time, current policy, current source state or an expected output as a constructor operand. Replay adds a distinct metered comparison phase; report construction and comparison work separately. It is a pure historical-data check, not the resource-qualified original-origin auditor.

## 3. What the pure authority checks prove

The constructor validates data relationships; it never authenticates a user, source or StoreRoot. The host must eventually obtain these inputs through the approved private root/source/assent/origin proof paths. No factory accepting an untrusted observation body may name its output `VerifiedAuthority` or `CheckedOriginals`.

For every consumed original and current slot, execute: exact enrollment/principal/source/namespace/customer/scope agreement; SourceState identity/revision/status and selected current grant; original ceiling and monotone narrowing; original binding/publication/accepted agreement/activation relations; role/catalog/instantiation/slot-terms coverage; original assent and digest/evidence linkage; current time interval and operation/read/submit-or-correct coverage; accepted quantities, units and named activities; original correction slot and every affected dependent slot. Current grant need not have the same Ref as original grant, but must retain the required original coverage. Work acceptance uses selected active binding; correction resolves original binding/plan/schema/context irrespective of a newer active policy.

Exact field proofs validate schema/field/evidence kind/source slot/subject/target/token/value against nominated-source attestation and its retained EvidenceVerification. Two fields needing distinct evidence kinds cannot share a mismatching assertion. Construct any VerifiedFact before hashing authority that refers to it. Original source authentication and earliest introduction of that verification are later host/origin obligations; matching hashes alone is not proof of them.

Per-action book/role/slot/funding, original quantity/exposure constraints and affected-obligation limits are checked from typed terms and the selected input graph. Whole-ledger balances, mutable funding reservations, complete index absence and all-ancestor future correction capacity remain explicit unresolved admission obligations. They are not silently satisfied by a draft. If an implementation omits any relational check listed here, it must return an explicit unsupported result for that branch, and the foundation is not complete for that branch.

## 5. Complete meter domains for the claimed draft

One `CoreMeter` starts before parsing/normalizing the command and supplied semantic data. Existing typed source normalization performed during compilation belongs to the compile meter and may be reused only through immutable `SelectedProgram`; unparsed scalar operands must not be prepared free at runtime. Raw facts first execute the existing typed normalization (for example integer `0001` normalizes to `1`); only then does the canonical scalar parser run. Do not reinterpret the06 canonical-integer helper as a stricter raw request grammar. Compile-time scalar preparation may be reused through immutable SelectedProgram, with its complete work charged at compilation; new quantities/revisions/times remain runtime operands. No saved counter or caller maximum bypasses execution. Configured limit is at most the existing1,048,576 compile/65,536 draft semantic work. Test limits may be smaller only to exercise exact refusal.

Phases are `parse_normalize`, `resolve`, `original_authority`, `current_authority`, `facts_evidence`, `graph_select`, `pricing`, `construct`, and (replay only) `compare`. Every executed semantic instruction, typed field/element visit, constraint test, set/member comparison, edge visit and Ref lookup charges1 **before** execution. Arithmetic comparisons, additions, multiplication, negation, absolute value, quotient/remainder, scalar-digit accumulation, percentage denominator construction and timestamp/revision/window arithmetic charge `1 + sum(max(1,ceil(bit_length(abs(operand))/64)))`. Operand and result magnitude remain≤512bits, with existing amount limits. Meter bookkeeping/limb measurement is mechanism, not recursive economic work. Input string scanning/canonical encoding/hashing consumes the separate byte counters; it is not an unmetered semantic permission check. Semantically inspecting a string or set still charges the relevant instruction/comparison.

Do not sum old489/234/68/kernel or940 family counters into a new whole total. Reuse functions only where their actual events enter the same executing meter. Emit phase/event/operand-limb/cost trace and total so independent review can identify omitted work. Source ordering/set algorithms may choose a deterministic implementation; its actual comparisons must be charged. Plan/body bytes do not contain instrumentation-specific counters. The initial selected fixtures are measured executions, not a universal future maximum.

Byte accounting reports separately: raw request bytes (≤256KiB), unique resolved body bytes/Refs (≤8MiB/4096), each canonical body (≤4MiB plus smaller kind bound), new-body bytes, and bytes scanned/encoded/hashed including repeated passes. Check lengths before materializing an over-limit output; no post-allocation budget claim. The canonical serializer may use a checked count pass followed by bounded write; both byte passes are counted. A returned draft satisfies its actual limits. Bounded heap/RSS/arena, full historical scratch/cancellation/resource envelope and installation Profile-B admission remain later proofs and are not implied by those logical counters.

Exact-limit test reruns the full constructor at observed work N and succeeds; N−1 reruns and refuses before the offending operation and returns no draft. Do the same for each changed phase branch, not a replay of an expected trace. Byte-budget mutation must refuse before allocating the oversized destination. Replay construction work must equal fresh construction with identical inputs; comparison work is additional and explicit.
