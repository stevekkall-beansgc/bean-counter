No author expectation or derivation program accompanies this handoff. Independently verify every source pin, all 333 unchanged definitions, the exact 11 clone patches, closed additionalProperties, all registry expanded payload tuples against dispatch, and both const metadata schemas. Then derive the following conditional vectors. Nothing here constructs production support or a private prepared candidate.

All fixture strings/numbers are ASCII and integers; JCS is canonical sorted-key compact JSON with no insignificant spaces. Sets are sorted unique by their JCS byte representation, preserving arrays otherwise. Raw SHA256 is lowercase hex without prefix. H(domain,value,version=1) is `sha256:` + SHA256(UTF8(`bean-counter/`+domain+`/`+version)+NUL+JCS(value)). This includes the inherited workflow-document tuple [body.schema,body]. No newline is included in JCS or domain input.

Resolve records in literal order. `$record:name` means that earlier derived exact Ref. `$hash:{domain,value}` means H of the resolved value. All other literal Ref anchors are deliberately opaque, not evidence of their bodies/custody. For `identity.type=document`, Ref digest is H(workflow-document,[schema,body]), ID wdoc_+digest hex, kind as given. For `identity.type=record`, ID is prefix+H(identity.domain,resolved identity.tuple) hex, digest H(workflow-record,[kind,input.scope,body]). Emit each named record as {body,canonical_hex,raw_sha256,ref}. Validate the resolved body against its named definition. The dependency's target is the exact original WorkRecord anchor and its terms Ref is the Binding anchor, not a future fabricated cost record. Capacity's original root anchor corresponds to literal stable root decision ID wdecision_aaa… in its identity tuple. These opaque associations are conditional.
