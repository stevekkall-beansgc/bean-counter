## 1. Two distinct facts, one private checked context

`VerifiedAuthorityHead` proves the exact source-lineage seeds from02 §2. It cannot authenticate omitted financial revisions merely because the source is unchanged.

`VerifiedFinancialHistory` proves the financial seed set below. It is a separate nonserializable capability, constructed by the existing private coordinator origin verifier under the **same actual held StoreRoot and read snapshot** as all source witnesses. It grants no authority and does not evaluate a new operation's price. Fresh authorization still intersects original/current source grants and accepted terms. No request supplies either capability or asserts that it exists.

`CheckedEconomicInputs` combines `(source_capabilities, financial_capability, complete_immediate_inputs, pending_operation_key, observed_at)` in memory. Every capability must match the same store/scope/mode/custody/snapshot and its exact locked-head pins. Before commit recheck current source, decision, family, chain, dependency and capacity heads under existing ordered locks; any change invalidates the relevant checked context. Root handle, snapshot token and authenticated current actor stay private. Existing max5 attempts/max3 lock expansions and original-key recovery ordering remain unchanged.

Source and financial observations are separately retained, named in the new economic operation/manifest and replayed together. A source observation is not widened silently. No successful financial receipt is permitted when either required witness is unavailable or its original verifier is missing.

## 2. Exact financial seeds and cut coverage

Start with the **complete coordinator-resolved immediate input set** for the pending operation, before producing any new journal/result. It is the set of exact immutable Refs supplied to pure core by the selected registered operation recipe: authenticated original subject/claim/target, original and locked current decision/family/chain heads, original/current active actions and inverse/basis records, original terms/binding/assent/roles, dependency reservations/capacity, schema/plan/context/verified facts, and descriptor/request evidence operands. It is not a caller-provided list and not just payload refs. Initial work has no current financial decision; its retained agreement/publication/source operands still participate. An operation with no prior financial heads has an empty financial head-pin list, not a fabricated revision0 decision.

Derive `preexisting_input_refs` by traversing all actual immediate Ref edges and required implicit recipe edges, stopping only at the closed history fields listed below and at code-owned verifier metadata. Exclude newly created records from this operation, including its new source observations, financial observation, new authority snapshot, new action/decision/head/capacity/result, and operation/manifest/receipt. Already-retained observations from **earlier** operations remain real retained inputs when their owning original record requires them. Inline uncommitted definitions, if a supported operation allows any, are validated separately under its own recipe and are not described as prior committed financial inputs.

For each retained input record, inspect these exact fields:

- `ledger-workflow-decision-revision/1.prior_ref`
- `ledger-workflow-family-state/1.prior_ref`
- `ledger-workflow-chain-state/1.prior_ref`

Every present field produces a closed `FinancialHistoryEdge {owner_ref,field,target_ref}`. `history_edges` is the canonical JCS set of **all** such edges on preexisting inputs, including edges whose target is also already an immediate input. Missing, extra, wrong-owner, wrong-field, changed-target and duplicate entries refuse. Only these three fields are financial cut edges. SourceState.prior_state_ref is covered by the separate source witness; it remains traversable in the full origin audit. Actions' inverse_of/basis, original terms, proofs, claims, targets and current dependency/capacity refs are not optional history.

`financial_seed_refs = unique(preexisting_input_refs ∪ {edge.target_ref for edge in history_edges})`. This deliberately includes current and original retained inputs, not just removed history targets, so their originating financial transition and input selection are both authenticated. `head_pins` is the exact set of checked current financial heads actually consumed by the operation, each `{kind,ref,revision}` where kind is decision/family/chain/capacity. The recorded revision must equal that record's body and its current locked projection; a historical original revision does not become a current-head pin. Add every head Ref to preexisting_input_refs. Multiple customers/chains cannot share a pin accidentally; actual immutable bodies and original scope/binding checks decide compatibility.
