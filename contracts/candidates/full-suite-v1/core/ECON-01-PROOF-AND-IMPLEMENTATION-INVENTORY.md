## Capacity and authority closure gate — concrete issue, no invented budget

Financial amendment §2.2 requires each accepted future monetary dependency to fit every still-correctable ancestor's complete atomic correction, including byte/ref/work budgets. `32 decisions / 128 actions` alone is insufficient. For the literal measured root, two root components plus one outcome require two decisions and at most five appended actions in a quantity correction. A zero/none outcome does not reduce this prospective reservation.

Authority anchors: `AGREEMENT-READY-AMENDMENT.md` §3 (lines27–35) defines strict subset-only source.restrict, immutable current/prior state and a verified current-state projection; §6 (line65) requires current-state chain ancestry and caps the complete closure at4096 refs/8MiB. The approved `FINANCIAL-AND-RECOVERY-AMENDMENT.md` §2.1–2.2 (lines26–44) distinguishes retained history from bounded resolution and requires every accepted prospective correction footprint to remain feasible. These sources, not a new expiry policy, create the proof obligation.

The generic verification-closure recipe currently follows every actual immutable Ref. `SourceState.prior_state_ref` can therefore grow the mandatory current-authority closure after repeated permitted source amendments, even though the monetary closure is still two decisions/five actions. Future field attestations and their required trust material can also enlarge the immutable evidence closure. A record containing profile maximum constants is not a proof that these future closures remain admissible. There is no honest finite reserved byte bound from the selected observed history alone.

The exact source-only counterhistory is `economic-lineage-counterhistory.json`, reproducible by `derive_economic_lineage_counterhistory.py`. Initial current-source dependency closure has7 refs; the selected correction projection has79. Each strict one-microsecond end-time restriction appends one new grant and one new state while preserving all relevant correction rights. At2,009 restrictions/revision2,010, source dependencies have4,025 refs and the economic dependency lower bound is4,097 refs (4,117,971 body bytes), with the same two decisions/five actions. **This is a structural growth witness, not a publicly admitted default-profile bug:** cumulative administrative manifests alone reach788,521,348 bytes and cross ProfileB256MiB at restriction1,171. All real ProfileB checks remain active. An end-to-end reachable counterexample or a sound maximum derived jointly from global admission and current authority verification still needs independent qualification. The author does not use raw SQL or waive the pool to pretend this long trace succeeds.

**Required reconciliation before a live dependency can be admitted:** pin whether the existing single-writer authenticated authority transition/store invariant permits a current SourceState to be verified from its retained authenticated prefix without recursively loading every historical state per economic operation, and specify the exact retained proof/read recipe; or require every authority/evidence transition that increases a still-needed correction verification footprint to preserve affected original reservations under the same ordered locks. Neither alternative may skip actual authorization, make a database index authoritative by itself, discard historical states, shorten correction rights, reset a namespace, or create an unreviewed checkpoint trust mechanism. The independent authority/financial reviewer must inspect the exact proposed reconciliation against existing AGR/financial contracts. This packet selects neither by inference.

Until resolved, the schema's DependencyRecord/CorrectionCapacity fields define required evidence, but the author projection deliberately emits no such records and no successful commit receipt. This does not transform a promised correction into a best-effort feature or declare historical rights expired. Unknown commits and existing legacy semantics remain unchanged.

Separately, `OWNER-CAUSAL-REVERSAL-DECISION.md` is pending. New live dependency admission cannot promise post-deadline causal reversals while that capability remains unsupported. An initial in-window event is not sufficient permission. No arbitrary finite root horizon is introduced.
