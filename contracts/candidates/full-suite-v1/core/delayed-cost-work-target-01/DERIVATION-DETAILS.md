# Exact independent output conventions

These rules define finite fixture derivation, not a replacement for full runtime validation. Resolve singleton `$derived` markers recursively, including nested patch values. Do not modify the literal source templates or context.

1. From work_template key/payload/source_namespace derive `claim_id = wclaim_ + H_workflow-work-claim([key.logical_store_id,key.scope,work.source_namespace,payload.business_operation_id,"completion"])` and `work_id = wevent_ + H_workflow-event([key.logical_store_id,key.scope,key.source,payload.external_event_id])`.
2. Resolve work_template.claim_id. WorkRecord Ref uses kind workflow-work, work_id, and digest sha256:+H_workflow-record([kind,input.scope,body]). Derive facts_digest as sha256:+H_workflow-claim-facts([customer,chain,status,activity,product_ref,policy_ref,fact_schema_ref,facts,links,binding_ref,invocation_refs,evidence_refs]); fixture has no occurred_at. This is the existing twelve-element tuple.
3. Resolve claim_template; its Ref uses kind workflow-work-claim and claim_id, same workflow-record digest framing. `ancestor_id = wdecision_ + H_workflow-decision([claim_id,"work"])`; `cost_id = wdecision_ + H_workflow-decision([input.scope,claim_id,input.supplier_component_slot,"cost"])`.
4. Resolve dependency_template. Dependency ID uses its actual ancestor_decision_id, dependent_decision_id and original_terms_ref; kind workflow-dependency and existing workflow-record digest. Derive `dependency_root = sha256:+H_workflow-dependency-set([dependency_ref])`. Resolve capacity_template; capacity ID is wcapacity_+H_workflow-correction-capacity([ancestor_id,"1"]), kind workflow-correction-capacity, same record digest. Its root_ref is a declared unresolved literal original decision anchor; no complete decision or capacity proof is asserted.
5. Each record result has exactly `{body,canonical_hex,raw_sha,ref}`. `raw_sha` is unprefixed SHA256(JCS(body)). Base output `records` maps work,claim,dependency,capacity to these results; `identities` maps claim_id,work_id,ancestor_id,cost_id; `dependency_root` is the prefixed set hash.
6. For each case copy resolved context/dependency/claim, apply dotted path patches at those roots, creating a missing leaf but no other default. Recompute candidate claim Ref and dependency Ref from patched bodies, using unchanged permanent claim_id and dependency's actual three identity operands. Accept iff: candidate dependency passes DelayedCostWorkDependency1; candidate claim passes WorkClaim; context store/scope/work_ref/work_claim_id/work_claim_ref/binding_ref/invocation_ref/supplier_component_slot/ancestor_decision_id/dependent_decision_id equal the original resolved context; candidate claim equals original resolved claim (all fields); dependency equals original resolved dependency (all fields); and original_declaration_present,prebill_reservation,authenticated_originals,all_ancestor_capacity_proved,original_and_current_rights are all exactly true. Equality here is the declared finite fixture predicate; runtime must perform the actual §1/§2 semantic checks, not trust these predicates. `stage` defaults prebill and may be prebill/finalized/corrected; it changes no original dependency operand.
7. Emit each case `{name,stage,accepted,candidate_dependency_ref,candidate_claim_ref}`; accepted cases additionally have `retained_dependency_ref` and `retained_target_ref`, refused cases omit them. Do not invent replacement state/receipt on refusal.
8. `alternatives` maps invocation and work_claim to diagnostic copies of the original dependency with only target_ref changed respectively to anchors.invocation or derived claim_ref. Return each record's four fields plus its `dependency_root` over that alternative singleton Ref. Neither alternative is authorized. They demonstrate stable-ID/body-digest separation and exact capacity-root effects.
9. `schema_negatives` emits `{name,valid}` for each supplied patch applied directly to the base dependency, validated against DelayedCostWorkDependency1. `lifecycle` is the three supplied stages mapped to `{stage,retained_dependency_ref,retained_target_ref}` from the unchanged original dependency; this establishes immutable linkage only, not unchanged mutable capacity/head state.
10. `metadata` maps profile.json,registry.json,delayed-cost-work-target.schema.json to unprefixed SHA256(JCS(file)); `registry_entries` is the new exact entries array. Top-level output keys are exactly records,identities,dependency_root,cases,alternatives,schema_negatives,lifecycle,metadata,registry_entries.
