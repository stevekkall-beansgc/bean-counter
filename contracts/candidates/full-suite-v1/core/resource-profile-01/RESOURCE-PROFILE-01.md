# RP01 — separate representation work; preserve financial semantics

Author candidate, 2026-10-16. Owner authorization and scope are WORK-ORDER.md in reviews/waves12/committed-bill-sprint-20261016. This additive amendment is not an admission qualification. Freeze requires independent review. Existing contracts and fixtures are unchanged.

## 1. Exact change and precedence

For the new, explicitly selected `workflow-resource-vector/1` execution profile only, this amendment replaces the **classification** of representation work in S12 §6's instruction/arithmetic accounting, r2-foundation/CONTRACT §5 and AUTHORITY-AUDIT-02 §4. Actual generic JSON syntax/duplicate-key/depth/integer decoding, canonical JCS representation traversal/key sorting/integer formatting, strict canonical base64 conversion and the owned buffer arithmetic executed inside the closed operations below are charged to a separate deterministic **C representation-work** dimension. They no longer debit the financial **S semantic-work** allowance. The same visit1 and bounded operand-limb arithmetic schedule applies in both dimensions; checks and callbacks are not removed. All exact bytes, errors, grammar and domain validation remain required. Source scan, encode/write, hash and I/O byte counts remain separate and count repeated passes.

Retain S limits: economic child65,536; compile1,048,576; original composed1,048,576 including its inner compile OR economic child and host framing/authority/relationship work. This is a changed guarantee/classification, expressly authorized here; a v2 execution is NOT evidence that the same input fits the old v1 accounting. Existing old descriptor/CompiledPlan.worst_case bytes remain historical metadata, not rewritten as v2 measurements. No new fixed numeric semantic ceiling or pool/structural increase is authorized.

All financial rules, original terms, exact money/rounding, semantic IDs, ordinary/correction rights, causal A, complete dependent closures, original/current authority, funding/exposure and Profile B remain normative. New profile does not authorize a draft, any unsupported executor, an incomplete original auditor, or a first bill without all promised future correction reservations. Original unchanged caps include smaller kind limits in addition to profile.json. The4MiB canonical-record bound is not a universal cap on every raw/container frame; each existing frame's bound remains exact.

## 2. Closed classification boundary

Decimal/ratio/quantity, Timestamp, FactSchema, Product, Policy, Ref parsing/association and set membership are semantic even when implemented using strings or numbers. A comparison does not become representation work merely because operands are JSON Values. There is no generic caller-selectable classification flag, callback closure, code label exemption, already-paid credit or trusted cached object. Allocation arithmetic belongs to C only when performed inside a named closed operation; elsewhere it remains paid under the executing S path. Destruction bookkeeping is prepaid in the same lease's creating operation. Nested calls consume the same owner, never obtain new allowances.

## 3. Finite source envelope, not a guessed codec ceiling

The only permitted C limit is the code-owned `closed-source-envelope/1` attached to the exact resource implementation/recipe support. It consists of finite source-derived bounds for each enabled operation and all its callers. Bounds are evaluated with checked arithmetic before the affected operation/reservation; overflow refuses without execution. The input maxima come from existing kind/recipe limits and observed lengths bounded by those maxima, never caller-provided coefficients or a caller maximum.

The source certificate identifies exact saved/fresh recipe tuples, source hashes, closed representation operation IDs, each call site's maximum multiplicity, bounded input/output shape and bytes, loop/branch counts, callback schedule, C/scan/write/hash upper expressions, S/composed allowance, retained/scratch/overlap/stack and I/O obligations. Expressions may use nonnegative constants, validated input dimensions, addition, multiplication, ceil-divide by a positive constant and minimum. No recursive expression/caller program is evaluated. Implementations compile these into typed private formulas; JSON proof metadata cannot manufacture a supported recipe or budget.

`SOURCE-COUNT.md` supplies an independently checkable concrete base64 kernel certificate. It is not a bound for JSON, a wrapper, a full origin, or an entire history. Those complete source certificates are REQUIRED before enabling the corresponding new-profile execution, and before financial admission. A missing proof is unsupported capability, not an infinite allowance. A measured successful fixture is not the missing certificate. Added callbacks/calls or changed source require bound re-review; unchanged semantic inputs must not be made to fit by suppressing executed work.

For one original, add all local C calls (including owned child compile/economic calls) once to its C envelope. Host and core share the same owner. Earlier origin verification has its own per-origin bound and joins the finite Profile-B history envelope; it is not secretly charged to each dependent's local limit nor exempted from traversal cost. Complete chronological audit still covers actual origins, earliest introduction, projections and indexes. No Noop validation path may qualify that audit. Historical memoization is invocation-local completed proof reuse only; no persistent trusted checkpoint is added.

Financial computation must be invariant under representation-only variations such as legal whitespace. They can change C/byte usage and operational completion time, not the economic allowance or amount. S/type/schema constraints remain paid and can legitimately refuse their unsupported semantic shape. Universal supported-recipe qualification must cover the entire existing legal representation envelope, not just compact fixture rows. If a finite complete envelope or a required S bound cannot be proved, stop with the exact obligation; do not raise diagnostic stops or run calibration.
