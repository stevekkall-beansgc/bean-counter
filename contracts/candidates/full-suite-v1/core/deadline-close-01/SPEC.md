## Deadline authority algorithm

1. Identity-first original handling and current read protection retain the existing rules. For a fresh close, resolve original target/family, original accepted Binding/Agreement, policy/product/trigger, frozen window/anchor, source nominations and accepted role/terms/ceilings. Do not use the current policy as the original. Inspect the actual current FamilyState and expected revision under the same final writer/CAS. Only awaiting_anchor or open can expire; all claimed and terminal states refuse. Deadline accepted_at is trusted and strictly greater than activation deadline D (awaiting_anchor) or accepted_by (open); equality refuses. Preserve received_at<=accepted_at and existing nonregressing trusted clock checks. No caller timestamp can manufacture expiry.
2. Authenticate the actual principal/source against current active enrollment/state/grant and exact installation/store/scope/customer. Derive candidates from the **complete original accepted Binding.source_slots**, never Family.source_slot, correction_source_slot or optional no_success_close by convention. A candidate slot must originally nominate that actual source. Its accepted role/terms and original ceiling must permit the same source/role association, exact original binding/target/product/trigger and operation outcome.close. Both original and current grants must explicitly permit outcome.close and BOTH rights close AND read, with all original/current source-slot, selector, customer, interval and role restrictions. No submit permission is required for this deadline branch; possessing submit alone is insufficient. Original grants are actual retained/authenticated original obligations, not caller lists; current grants cannot enlarge the accepted original scope. No union of partial permissions across candidate slots is allowed. All checks and set derivation are paid in their existing domains.
3. Form the complete set of individually sufficient slot names. Duplicate original slot definitions/ambiguous semantic identities refuse according to existing closed binding rules. Sort by canonical JCS encoding of each name under existing set rules; choose the first. Empty set refuses. This tie-break operates only among independently complete authorizations, not among partial evidence. Input array order must not affect the result. Retain selected source_slot and exact original grant/authority evidence in EconomicAuthority5, along with all other required authority fields. Applicable current/original grant set resolution follows the existing binding/source recipe; selecting a slot cannot choose a weaker historical ceiling. For a deadline close, rights records exactly the exercised canonical set [close,read], not arbitrary unexercised permissions. Causal/cost/invocation context fields retain the complete operation-specific supplier recipe, not forced empty in production.
4. Recheck actual current role/source/expiry/revocation, trusted time, head and snapshot before committing. Queue/preparation status is not financial acceptance and reserves no deadline. Revocation or expiry while preparing prevents new close; do not backdate. A CLI/scheduler service source must itself satisfy the same original/current rule. LocalOwnerAdmin, scheduler label, a namespace string, a hash or a new capability cannot fill missing authorization. No privileged fallback is created.
5. Produce FamilyState expired with exact new revision/prior head, unchanged original target/family/window/anchor and canonical supplemental payload evidence_refs as closure_evidence_refs. No outcome claim/decision/action/fee or business no-success assertion is created. Release only expiry-eligible original contingent hold once, preserving every remaining claimed-family correction, ancestor, supplier and high-water obligation. A source is not allowed to supply release amount; core derives it from actual original/current reservations. The same atomic journal/result/receipt and all resource/capacity/ownership/CAS gates apply. Original retry returns its verified original result, not a second release; another-key stale or terminal request cannot release twice.
6. No-success remains exactly the frozen explicit original `no_success_close.close_source_slot` + typed family_no_success assertion/verification recipe, including its actual original/current operation/permission rules. It does not inherit this deadline slot selection or reduced evidence. Deadline authority grants no early/no-success power. Conversely a no-success nomination is not a deadline fallback. No-success proof pair stays explicitly consumed in authority/manifest; FamilyState.closure_evidence_refs remains the normalized payload evidence_refs, not a silently enlarged set.
