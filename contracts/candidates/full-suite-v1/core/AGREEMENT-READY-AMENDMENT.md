# AGR-02 — repaired agreement boundary and local prerequisite operations

Astra candidate, 2026-10-13. Supersedes AGR-01 only as enumerated here; no existing frozen file, prior known oracle or support catalog is changed. Fresh independent review required. Profile B is approved; full Wave2 execution remains pending. This packet makes the local prerequisite families concrete using existing stable `evidence.retain` and `authority.change` operations; it adds no remote identity provider, signature scheme, commercial consent rule or globally unique source guarantee.

Authority basis: S12 plan §3.3 requires actual/synthetic assent appropriate to installation mode, §7 requires current source authority and original ceilings, §15.1 separates publishing from acceptance, §15.6 defines immutable descriptor anchors; CORE §6 requires the evidence behind authority refs. The published local model already records mode real, acceptor, retained evidence, operator and operator_attestation (`crates/ledgerlab/src/service/billing.rs:511`, `domain/records.rs:83`). The proposed resolver applies that accountable **local operator-attested** trust model to generic terms. It does not claim a hash is customer authentication or that being administrator establishes assent.

## 1. Activation selection, expiry and cancellation (replaces AGR-01 §4)

Activate/replace must select a binding valid at the new effective boundary: starts_at≤effective_at<ends_at if end exists. Revoke is a cancellation/admission stop; **never require binding validity at revoke time**. It may revoke the current unsuperseded pending transition before starts_at or revoke an already effective selection after ends_at. It requires current administrative authority, target agreement ownership and current activation-head CAS, not assent to new prices. Revoke appends effective_at=trusted commit time and supersedes/cancels the nominated current selection and pending selection horizon, without changing old work or outstanding liabilities.

Projection algorithm: first remove only transitions explicitly superseded by a valid replace/revoke edge for selection purposes; replacement edges apply to the pending transition, not to previously effective historical intervals. Retain every record for audit. At admission time t choose the latest committed **boundary** with effective_at≤t ordered by (effective_at,commit_sequence), including revoke boundaries, before testing binding validity. A selected revoke means no admission. Otherwise test selected binding validity at t; expiry means no admission. Never scan backwards to an older valid binding. Pending future boundaries do not become eligible early. When revoke cancels a pending future boundary, that future boundary cannot later spring back into eligibility. New activation can resume only by explicit authorized transition; old indefinite terms never resume automatically.

Schedule history vector: v1 starts0/noend, active at0; v2 starts10/ends20, scheduled at10 while trustedtime5. Revoke pending v2 at6 is valid, gives no admission at6 or10; v1 histories before6 remain unchanged. Separate run without revoke: at9 selects v1,10 and19 selectv2,20 and21 selectnone. Replace pending10 with15 at6: at14v1,15v2,20none. Replacement at original boundary10 is forbidden because pending is no longer strictly future. Equal-time authorized boundaries use commit_sequence; higher sequence wins, never publication or acceptance revision. Revoke expiredv2 at21 remains valid and records an explicit stop, not an inverse. Author `validate_agreement_ready.py` checks these logic histories as contract examples; it is not a product oracle.

## 2. Immutable evidence and installation trust root

Root capability is the reviewed non-request-constructible LocalOwnerAdmin. Installation mode `real_local` or `isolated_synthetic` is trusted installation configuration, retained with enrollment authority observation; no operation sets it. Existing installations default to real_local. Test mode is explicit test setup, has no dispatch capabilities, is never inferred from a request/source/customer string. No new remote/delegated route is enabled. A hostile trusted local administrator remains outside the local authenticity claim.

EvidenceRetain payload is exact `ledger-workflow-evidence-retain/1`: purpose enum customer_registration|source_enrollment|assent|operator_attestation|funding, subject{customer,agreement_id?}, media_type text/plain;charset=utf-8|application/octet-stream, content_base64, content_sha256, metadata. All schema/purpose/body fields must agree. Raw bytes≤4096; strict standard padded base64, re-encode exact canonical spelling; content_sha256 raw lower64hex equals bytes. This retains local proof material, not an imported proof of truth. Authoritative fact attestations/supplier evidence remain distinct future families.

EvidenceRecord is the same fields with schema `ledger-workflow-retained-evidence/1` plus retained_by,retained_at,installation_mode,authority_ref. It uses workflow-evidence/wdoc identity. These derived fields come from actual local actor/time/root snapshot. Operator-attestation evidence requires actual actor equal the AssentRecord.operator and verifies its referenced assent evidence exists, same subject/acceptor/terms and matching declaration. Local operator must explicitly submit the statement; server must not fabricate an attestation from its held lock. Stored text/bytes, structured metadata and subject are retained together; a later changed narrative cannot reuse the same identity.

New evidence operation requires LocalOwnerAdmin and source mapping as for other local admin operations. Same original key uses prior read/evidence first. New-key same purpose+subject+raw bytes+metadata is a semantic alias reusing original EvidenceRecord/time; original content projection excludes retained metadata. Current read is local-admin store/scope read; source access needs actual enrolled read rights. Root/scope checks precede disclosure.

## 3. Customer and generic source enrollment

SourceEnrollmentRecord pins this immutable ceiling, exact registered customer refs, evidence, actor/time/root/mode. Enrollment ID key(store,scope,enrollment_id) is permanent. - `source.restrict`: enrollment_ref,expected_revision,replacement_ceiling. Names-selector subset is exact set containment; namespace selector can narrow to same namespace or explicit names within it, never expand. All dimensions must remain closed/bounded. - `source.revoke`: enrollment_ref,expected_revision,reason. Appends revoked SourceState revision=old+1 with no current grant. Re-enrollment under a new enrollment ID does not change canonical source namespace or bypass original work claims. Re-enabling a revoked enrollment/expanding old rights is unsupported here; future explicit enrollment can authorize future work only under its own reviewed evidence and original ceiling.

SourceState retains enrollment_ref,revision,status active|revoked,current_grant_ref (required active, absent revoked),prior_state_ref optional only revision1,operation_key,actor,accepted_at. All are exact immutable records; current-state index is a verified projection. Initial source enrollment and initial SourceGrant/State commit atomically. Authority.change returns exact registration or enrollment/grant/state refs; operation schema allows no raw journal append.

Canonical source registry is installation/scope-local. An existing source alias mapping cannot be reassigned to another economic namespace by a later enrollment/customer/policy. First registration requires source==canonical_economic_namespace in this bounded local profile, matching current verified local source; additional alias/credential-registration variants remain unsupported. Multiple enrollment IDs may narrow one canonical source for A/B customers, but neither grants cross-customer access. No cross-installation uniqueness guarantee is added. This applies approved S12 permanent economic namespace rules, not a new business identity requirement.

The actual resolver loads original SourceEnrollmentRecord+commit membership, registered customers/evidence/root, latest SourceState/current grant under ordered source locks; validates source/state lineage/CAS, original ceiling subset, current time, principal and installation mode. Local source caller must come from the existing authenticated local source route mapped by trusted configuration; request `source` is never authentication. Generic operations/selectors authorize business names as data. Legacy Setup read/submit/correct does not satisfy these grants, and a current SourceGrant shape cannot self-enroll. Ordinary agreement administration uses LocalOwnerAdmin **plus** real registered customer assent and valid bound generic source; it never treats source submit permission as terms administration.
