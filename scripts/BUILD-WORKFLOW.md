The initial workflow build capture uses `python3 scripts/build_workflow.py --output /private/tmp/NEW-DIRECTORY` for the default release CLI, or adds `--test` to compile test binaries without running them. `--capture-only` writes source metadata and qualifies no executable. Activate the pinned Rust 1.98.1 toolchain and an isolated Cargo cache containing only locked dependencies first.

The wrapper captures selected raw source bytes, records the actual git base and scoped clean/snapshot state, and builds from a copied source tree. It checks that captured inputs remain unchanged after compilation. The retained output contains the source inventory, canonical BuildInputs, captured tree and build artifacts. This is a local source/build observation; it does not certify independent authenticity or reproducibility.

Tool observations and the build use an explicit environment containing PATH, HOME, CARGO_HOME, RUSTUP_HOME, RUSTUP_TOOLCHAIN, TMPDIR and LC_ALL=C. Other ambient variables are not forwarded. This first recipe refuses explicit compiler/flag overrides, Cargo configuration discovered from the source or actual capture directory, submodules, escaping/symlink inputs and undeclared repository build scripts. It supports default package features and target, empty explicit Rust flags, and locked offline dependencies.

`ledgerlab/build.rs` embeds the wrapper's build-time artifact. Ordinary Cargo builds embed no qualified BuildInputs and fresh workflow publication must return BUILD_IDENTITY_REQUIRED. Original status/retry reads do not use current build identity. The private coordinator must validate the closed BuildInputs record and actual builtin compiler reference before creating executable provenance; this capture checkpoint alone does not enable publication.
